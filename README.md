# 문피아 무료편 다운 — FlaskFarm 플러그인

문피아 모바일 웹의 무료 웹소설 회차를 TXT로 저장하고, 받은 회차를 표지·삽화가 포함된 EPUB 합본으로 만드는 플러그인입니다. **v0.3.1**입니다. 로그인해야 열리는 무료 회차를 위해 로그인 쿠키를 선택적으로 등록할 수 있습니다. Cookie-Editor 등의 여러 줄 JSON 내보내기와 기존 Cookie 헤더 형식을 지원합니다.

## 지원 기능

- 모바일/PC 작품 URL 또는 작품 번호로 회차 분석
- 로그인 쿠키 저장·삭제 및 문피아 로그인 상태 확인
- 무료 회차만 선택 다운로드: 실행 직전 서버 목록의 `free=true` 재확인
- 작품 목록 자동 수집, 분 단위 스케줄, 작품당 실행 상한
- TXT 원자적 저장, SQLite 이력, SHA-256 기반 중복·손상 검사
- 중지와 FF 재시작 이후 완료 이력 유지
- 숫자 회차 순서대로 EPUB 합본 생성, 고유 작품 ID 사용
- TXT 첫 줄에 `34. 유령선` 형식의 번호·제목 추가
- 작품 폴더에 `cover.jpg`, ComicInfo 형식의 `info.xml` 저장
- EPUB 표지 첫 페이지, 원래 본문 위치의 삽화, 조절 가능한 줄간격·문단 간격
- 기존 TXT 제목 보완, 예전 회차 삽화 복원 및 EPUB 재생성
- 오류/실패 회차 표시, 다음 실행에서 재시도
- 다른 FF 프로세스와 중복 실행 방지 (Linux 파일 잠금)

구매 회차·골드 결제·대여권 사용은 포함하지 않습니다. 쿠키를 등록해도 목록에서 `free=true`인 회차만 받습니다. 앱 전용·성인 인증 등 접근 제한을 변경하지 않습니다. 문피아 본문이나 사용자 쿠키는 이 저장소에 포함하지 않습니다.

본문 삽화는 TXT에 `[삽화: images/파일명]`으로 위치를 표시하고 실제 파일은 작품 폴더의 `images/`에 저장합니다. EPUB에는 이미지를 내장하므로 별도 인터넷 연결 없이 볼 수 있습니다. 이미지를 받지 못해도 TXT는 유지하고 화면에 이미지 경고를 표시합니다.

## Git 저장소 구성

저장소는 [endells/munpia_free](https://github.com/endells/munpia_free)입니다. 저장소 최상위에 다음 파일들이 있습니다. 별도로 배포할 경우 `munpia_free` 폴더를 한 겹 더 넣으면 FF가 찾지 못합니다.

| 경로 | 역할 |
|---|---|
| info.yaml | FF 플러그인 정보 |
| setup.py | 플러그인·메뉴 등록 |
| mod_basic.py | 설정·명령·스케줄 연결 |
| core.py | 모바일 API·다운로드·DB·작업 제어 |
| publication.py | 표지·ComicInfo·삽화·EPUB 생성 |
| templates/munpia_free_basic.html | 설정·분석·상태·이력 화면 |
| tests/ | 본문이 포함되지 않은 합성 데이터 시험 |

`info.yaml`의 home은 `https://github.com/endells/munpia_free`입니다. 다른 계정에 배포할 경우 home을 해당 주소로 바꾸세요.

## GitHub 연결과 키

공개 저장소를 FF에서 복제하는 데 GitHub API 키는 필요하지 않습니다. 비공개 저장소는 컨테이너의 별도 Git 인증 설정이 필요합니다. FF 설치 편의상 공개 저장소가 가장 간단합니다.

ChatGPT의 GitHub 연결 권한과 FF 컨테이너의 Git 인증은 서로 별개입니다. 연결된 계정에서 저장소를 만들고 ChatGPT 연결의 접근 범위에 추가하면, 지원되는 연결 기능으로 소스를 올릴 수 있습니다. 토큰이나 비밀번호를 소스·README·채팅에 넣을 필요가 없습니다.

## FF 설치

대상 환경: 사용자 제공 `flaskfarm/flaskfarm:4.0` Linux 컨테이너. 이미지 태그와 실제 앱 버전은 다를 수 있습니다. Python 3.8 이상, FF가 제공하는 Flask/plugin/framework 기능을 사용합니다. 이미지 검증·변환에는 FF 공식 requirements_mini.txt에 포함된 Pillow를 사용합니다. import 시 pip 설치를 실행하지 않으며, Pillow가 없는 환경에서는 이미지 경고를 표시하고 TXT 수집은 계속합니다.

1. FF의 **시스템 → 플러그인 관리**에서 설치 주소 `https://github.com/endells/munpia_free`를 입력합니다.
2. 확인한 FF 설치기는 `.git`을 자체 추가하므로 **뒤에 `.git`이나 `/`를 붙이지 마세요.**
3. 설치 후 FF를 재시작합니다.
4. **문피아 무료회차 → 설정**에서 다운로드 폴더와 작품 목록을 저장합니다.
5. 처음에는 **회차 선택 → 작품 분석 → 1개 회차 선택 → 선택 회차 받기**로 확인합니다. 시험 작품 주소: `https://m.munpia.com/novel/detail/599040`.

사용자 컨테이너에 설치해 보지 않았으므로 메뉴 이름/설치 경로가 실제 FF 버전에 따라 다를 수 있습니다. 설치 오류는 해당 시점의 FF 로그로 확인합니다.

## 로그인해야 열리는 무료 회차

작품 599040에서 비로그인 상태의 5화 본문은 열리지만 6화는 HTTP 400, `A002_21006` (로그인 후 이용해주세요)으로 거부되는 것을 확인했습니다. 목록의 무료 표시는 비로그인 열람 가능 여부와 다릅니다.

1. PC Chrome 또는 Edge에서 `https://m.munpia.com`에 로그인하고 작품 페이지를 엽니다.
2. Cookie-Editor 등 쿠키 확장프로그램에서 **현재 사이트의 쿠키를 JSON으로 내보내기/복사**합니다.
3. `[`부터 `]`까지 JSON 전체를 복사합니다. 줄바꿈·들여쓰기를 그대로 두세요.
4. FF의 **문피아 무료회차 → 설정 → 문피아 로그인 쿠키**에 붙여넣습니다. JSON 배열과 `{"cookies": [...]}` 형식을 지원하며 최대 256KB, 1000개입니다.
5. **로그인 확인**에서 성공 여부를 확인하고 **설정 저장**을 누릅니다. 로그인 확인만 누르면 새 쿠키는 저장되지 않습니다.
6. 작품당 최대 회차 수를 필요에 따라 50 또는 100으로 설정하고 저장한 후 다시 받습니다. 이미 완료된 정상 파일은 건너뜁니다. 기본값 10은 작품의 전체 회차 수가 아닌 한 번의 실행 상한입니다.

JSON에서 `domain`, `name`, `value`를 읽고 `hostOnly`, `path`, `expirationDate` 또는 `expires`, `session` 조건을 적용합니다. 모바일 호스트에 맞지 않는 쿠키와 만료된 쿠키, 파티션 쿠키는 제외합니다. 같은 이름이라도 경로가 다르면 요청 경로에 맞춰 사용합니다. `www.munpia.com` 또는 `nssl.munpia.com` 전용 쿠키를 모바일용으로 바꾸지 않으므로 반드시 로그인한 **m.munpia.com 페이지에서** 내보내세요. 저장할 때도 도메인·경로·만료 정보를 유지합니다.

기존 Cookie 헤더도 계속 사용할 수 있습니다. F12 → Network에서 모바일 문피아 요청의 **Headers → Request Headers → Cookie** 값을 복사하세요. 형식은 `이름=값; 이름=값`이며 `Cookie:` 접두사도 허용됩니다. 이 방식은 한 줄 최대 16KB입니다. `Set-Cookie`나 Netscape 텍스트 형식은 지원하지 않습니다.

쿠키 칸은 저장 후 비워지며 기존 값은 화면에 다시 보내지 않습니다. 빈칸으로 설정을 저장하면 기존 쿠키를 유지하고, **저장 시 기존 쿠키 삭제**를 체크하고 저장하면 삭제합니다. 쿠키는 `{FF 데이터 경로}/db/munpia_free_cookie.txt`에 파일 권한 `0600`으로 저장됩니다. 암호화 저장은 아니므로 FF 데이터 백업에도 인증정보가 포함될 수 있습니다. 계정 쿠키를 채팅·GitHub에 올리지 말고 접근을 신뢰하는 FF에서만 입력하세요.

문피아 로그인 확인 API의 `login` 값으로 인증 상태를 확인합니다. 쿠키는 `https://m.munpia.com`의 정해진 조회 API에만 보내며 리다이렉트를 따라가지 않습니다. 로그인 오류 코드 `A001_11004` 또는 `A002_21006`이 나오면 현재 작업의 나머지 회차 요청을 멈추고, 이미 받은 TXT 및 EPUB을 유지합니다. 다시 로그인해 새 쿠키를 저장한 뒤 재실행하세요. 사이트가 IP·브라우저 등에 세션을 제한한다면 쿠키를 입력해도 인증이 실패할 수 있습니다.

## 저장 경로와 운영

**다운로드 경로 → 경로 선택**을 누르면 FF 기본 폴더 선택창이 열립니다. 폴더를 찾아 선택한 다음 **설정 저장**을 눌러 적용하세요. 입력된 폴더가 아직 없거나 읽을 수 없으면 열 수 있는 가장 가까운 상위 폴더에서 시작합니다. 직접 경로 입력도 가능하며, 새 하위 폴더는 첫 다운로드 때 생성됩니다.

시놀로지 NAS에서도 같은 방식으로 사용합니다. 선택창은 **FF 컨테이너 내부 폴더**를 표시하므로 NAS의 모든 공유 폴더가 자동으로 보이지는 않습니다. 예를 들어 NAS의 `/volume2/도서`를 도커 내부 `/books`에 연결했다면 `/books/웹소설 다운`을 선택하거나 입력하세요. 양쪽을 `/volume2/도서`로 동일하게 연결했다면 `/volume2/도서/웹소설 다운`을 사용할 수 있습니다. 폴더가 보이지 않으면 Container Manager 또는 Portainer에서 FF의 볼륨 연결과 쓰기 권한을 확인하세요.

기본 다운로드 폴더는 `{FF 데이터 경로}/downloads/munpia_free`입니다. NAS 경로가 아닌 **컨테이너 안에서 보이는 쓰기 가능한 절대 경로**를 지정하세요. 예를 들어 NAS 폴더를 컨테이너의 `/books`로 연결했다면 `/books/munpia`를 입력합니다. 기존 volume 매핑을 확인한 후 선택하세요.

결과 예시:

- `작품명 [작품ID]/00001_회차제목 [회차ID].txt`
- `작품명 [작품ID]/작품명 [작품ID].epub`
- `작품명 [작품ID]/metadata.json`
- `작품명 [작품ID]/cover.jpg`
- `작품명 [작품ID]/info.xml`
- `작품명 [작품ID]/images/회차ID_순번.png` (또는 jpg/gif)

표지는 실제 JPEG로 저장하며, 작품 폴더에 표지가 없을 때 받습니다. `info.xml`은 ComicInfo 루트와 Title, Series, Writer, Penciller, Summary, Genre, Tags, Publisher, LanguageISO, Web, Count, 발행일 등의 필드로 구성됩니다. 작품 설명·태그가 없는 경우 해당 필드는 비워지거나 생략됩니다. 기존 파일 보완 시 작품 정보도 갱신합니다.

TXT 예시:

```text
34. 유령선

본문 첫 문단…
```

EPUB 기본값은 줄간격 **1.8배**, 문단 아래 간격 **0.55em**, 왼쪽 정렬, 강제 들여쓰기 없음입니다. 연속 빈 문단을 쌓지 않고 원문의 문단과 장면 구분을 정리합니다. 글자 크기는 상대 단위이고 글꼴·색상을 강제로 고정하지 않아 리더 앱의 크기·글꼴·야간 모드를 사용할 수 있습니다. 리더 앱이 자체 서식을 우선하면 앱 설정에 따라 표시가 달라질 수 있습니다.

## 기존 파일에 새 서식·삽화 적용

1. FF에서 플러그인 업데이트 → FF 재시작 → 페이지 새로고침합니다.
2. 설정에서 EPUB 합본 사용을 켜고 원하는 줄간격·문단 간격, 회차 상한을 저장합니다.
3. **수동 다운로드**에 작품 주소를 입력하고 **이 작품 기존 파일 보완**을 누릅니다. 여러 작품은 설정의 **저장된 목록 기존 파일 보완**을 사용합니다.

기존의 정상 TXT에는 번호·제목을 한 번만 붙이고 무결성 이력을 갱신합니다. 표지·info.xml을 보완하고 EPUB 사용 시 합본을 다시 만듭니다. 이전 버전에서 삽화 정보가 없던 회차는 본문·첨부 목록을 다시 조회하므로 쿠키가 필요할 수 있습니다. 재조회는 여전히 무료인, 이미 받은 회차에 한하며 작품당 회차 상한이 적용됩니다. 34편이라면 상한을 50 이상으로 설정하면 한 번에 보완할 수 있습니다. 완료된 보완은 다음 실행에서 건너뜁니다.

새 다운로드부터는 회차의 본문·삽화 위치를 작품 폴더의 `.munpia_free/entries/`에 보관합니다. 이 자료는 EPUB 재생성과 이미지 재시도에 사용하므로 `images/`와 함께 유지하세요. 이미지 재시도는 저장된 원본 정보를 사용하고, 누락된 예전 원본 정보만 문피아에서 다시 조회합니다. 표지·본문 이미지는 문피아 HTTPS 주소만 지원하며 다른 호스트로 인증 쿠키를 전송하지 않습니다. JPEG/PNG/GIF 및 Pillow가 지원하는 WebP를 처리합니다. WebP는 EPUB 호환성을 위해 PNG로 변환하고 SVG·외부 사이트 이미지 등은 경고와 자리 표시로 남깁니다.

이력은 `{FF 데이터 경로}/db/munpia_free_history.db`, FF 설정은 별도 FF 설정 DB에 저장됩니다. FF 데이터 볼륨을 유지해야 재설치/재시작 후에도 이력이 보존됩니다. 실제 다운로드 파일과 SHA-256이 맞아야 건너뛰며 파일이 없거나 손상되면 재수신합니다.

기본값은 작품당 10회차, 요청 간격 1.5초, 자동 수집 간격 180분, 자동 수집 OFF, EPUB ON, 작가의 말 OFF입니다. 수동 선택에도 작품당 상한이 적용됩니다. 설정 저장은 작품 목록과 설정만 반영하며 즉시 다운로드를 시작하지 않습니다. 자동 수집을 켜거나 실행 간격을 변경하면 지정한 간격이 지난 뒤 첫 예약 수집을 시작합니다. 작품 목록·경로·쿠키만 바꾸는 경우 기존 예약 시각을 유지합니다. FF 재시작 후에도 첫 수집은 지정한 간격이 지난 뒤 실행합니다. 즉시 수집하려면 `저장된 목록 지금 받기`를 누르세요. 자동 수집을 끄면 예약을 해제합니다.

다운로드가 끝난 TXT는 원자적으로 교체한 뒤 완료 이력을 남깁니다. 취소·연결 실패 중의 파일은 완료로 기록하지 않습니다. TXT를 받은 뒤 EPUB 생성 중 취소되면 다음 실행에서 EPUB을 다시 만듭니다. 진행 중 네트워크 요청은 최대 타임아웃까지 기다릴 수 있습니다. FF 전체 프로세스를 강제 종료하지 않습니다.

폴더 경로를 바꾸면 새 경로에 파일이 없으므로 다시 수집합니다. 작품명이나 회차명이 바뀌더라도 기존 정상 파일은 이력으로 인식합니다. EPUB 생성 시 새 작품 제목 폴더에 합본이 생성될 수 있으며 옛 폴더는 자동 삭제하지 않습니다.

## 검증

로컬 합성 데이터 시험:

```bash
python -m unittest discover -s tests -v
```

URL 검증, 무료 선별, 선택 ID 검증, 모바일 커서 페이지 처리와 반복 감지, 빈 본문 거부, 파일 무결성·재시도, 파일 잠금·취소, 경로 이탈 방지, EPUB ZIP/XML·회차 순서를 검사합니다. 별도 Flask/Jinja가 있는 테스트 환경에서는 FF 연결 어댑터의 설정·명령·화면을 모의 시험합니다.

v0.3.0에는 합성 이미지로 표지의 실제 JPEG 변환, ComicInfo XML, EPUB 표지·삽화의 매니페스트 연결과 본문 순서, 기존 TXT 제목 보완의 중복 방지, 삽화 실패 후 캐시 기반 재시도, 서식 변경 후 EPUB 재생성, 이미지 요청에서 쿠키 제외를 검증하는 시험을 추가했습니다. 실제 문피아 표지의 다운로드·JPEG 변환과 본문 첨부 이미지 응답 구조도 확인했습니다.

실제 문피아 작품 599040의 목록·비로그인 무료 본문과 6화의 로그인 필요 응답, 비로그인 계정 상태 API를 확인했습니다. 사용자 계정 쿠키로 6화 이후를 받는 실환경 시험은 아직 진행하지 않았습니다. 합성 데이터 시험에는 쿠키 전달·출력 비노출·저장 권한·삭제·로그인 오류 중단·재시도가 포함됩니다. 작품 전체 본문을 시험용으로 수집하거나 패키지에 넣지 않았습니다. 자동화 시험 통과는 실제 FF 컨테이너 호환성이나 모든 문피아 작품 지원을 보장하지 않습니다.

## 현재 제한과 다음 단계

- 구매 회차 지원은 후속 작업입니다. 로그인 세션으로 구매 여부 및 본문 접근을 별도 검증해야 합니다.
- 무료 회차라도 앱 전용·성인 인증·서비스 종료 등으로 접근이 제한될 수 있습니다.
- 사이트 응답 형식이 바뀌면 API 분석과 플러그인 업데이트가 필요합니다.
- 이 버전은 제목 검색/연재 추천 목록, 회차별 EPUB, 웹훅 알림을 지원하지 않습니다.
- 동시에 여러 FF 웹 프로세스를 운영하는 환경에서는 실행 잠금은 공유하지만 진행 화면 상태는 프로세스별입니다. 일반적인 단일 FF 웹 프로세스를 기준으로 합니다.

FlaskFarm의 공식 공개 플러그인 인터페이스를 확인해 새로 구현했습니다. `kaka_pe_dl`의 암호화 코드를 복호화하거나 그 소스를 복사하지 않았습니다.

## v0.3.2 화면 정리

작업 상태를 모든 화면의 제목 바로 아래에 작은 패널로 배치했습니다. 본문 안의 중복 메뉴를 제거하고 FF 상단 메뉴의 회차 선택을 수동 다운로드로 바꿨습니다. 오류는 발생할 때만 표시하며 중지 버튼과 진행률은 상단에서 확인할 수 있습니다.

## v0.3.3 파일명 번호 자릿수

설정의 **파일명 회차 번호 자릿수**에서 1~10자리를 입력할 수 있습니다(기본 5). 34화는 3자리일 때 `034_제목 [회차ID].txt`, 4자리일 때 `0034_제목 [회차ID].txt`로 저장합니다. 새로 다운로드하는 파일부터 적용하며 기존 파일명과 TXT 본문의 회차 제목은 바꾸지 않습니다. 설정보다 긴 번호는 잘라내지 않습니다.
